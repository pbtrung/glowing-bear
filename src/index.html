Connect to WeeChat

{{ authErrorMessage || 'Wrong password.' }}

WeeChat 4.1 or later is required.

Glowing Bear connects to the "api" relay of your WeeChat. All communication goes directly between your browser and your WeeChat: your server must be reachable from this device. Nobody else sees your data or your password, and all settings, including your password if you choose to save it, stay in this browser.

Quick start (unencrypted, for local testing)

/set relay.network.password y0ur_StRonG-pa$sw0rd:of*choice
/relay add api {{ settings.port || 9001 }}

Use TLS encryption

With encryption, all communication between your browser and WeeChat is encrypted with TLS. This needs a certificate. Self-signed certificates are handled poorly by browsers and may not work at all on mobile devices, so we recommend a free certificate from Let's Encrypt.

If you don't have a domain you can get a free subdomain from providers such as afraid: set up an A record (and an AAAA record for IPv6) to your server's address.

Getting a certificate: follow the instructions at certbot.eff.org (if you already run a web server, you can also proxy the relay through it, see our wiki). Then get the certificate with certbot certonly --standalone -d {{ settings.host || 'your.domain.com' }}.

Copy it where WeeChat expects it, replacing username with your user:

mkdir -p ~username/.config/weechat/tls
cat /etc/letsencrypt/live/{{ settings.host || 'your.domain.com' }}/{fullchain,privkey}.pem > ~username/.config/weechat/tls/relay.pem
chown -R username:username ~username/.config/weechat/tls/

Then set up an encrypted relay on port {{ settings.port || 9001 }}:

/set relay.network.password y0ur_StRonG-pa$sw0rd:of*choice
/relay tlscertkey
/relay add tls.api {{ settings.port || 9001 }}

Certificates must be renewed every few months (certbot renew). After renewing, copy the certificate again and run /relay tlscertkey in WeeChat.

TOTP (Time-based One-Time Password)

WeeChat expects the TOTP in an HTTP header that browsers can't send on WebSocket connections, so TOTP can't be used with Glowing Bear. Make sure relay.network.totp_secret is empty.

Pinning buffers

With "Only show buffers with unread messages", pinned buffers stay visible. To pin a buffer, type /buffer set localvar_set_pinned true. Local variables are not kept across WeeChat restarts: use the script buffer_autoset.py or a trigger to pin buffers automatically, for example (for irc.libera.#weechat):

/trigger add autopin signal "buffer_opened" "${buffer[${tg_signal_data}].full_name} =~ irc.libera.#weechat" "" "/command -buffer ${buffer[${tg_signal_data}].full_name} * /buffer set localvar_set_pinned true"

Host field and custom path

Glowing Bear connects to {scheme}://{host}:{port}/{path}, where the scheme is https/wss with TLS and http/ws without, and the path is api unless the relay is behind a proxy. The host field accepts:

  • 192.168.0.1, [2001:db8::7334], weechat.example.com
  • weechat.example.com:8000 (host and port)
  • weechat.example.com:443/relay/api (host, port and path; the port is required with a path)

IPv6 addresses must be wrapped in square brackets.

URL parameters

Fields can be prefilled from the URL, which is handy for bookmarks: #host=weechat.example.com&port=8000&autoconnect=true. Available parameters: host, port, path, password, autoconnect. Passing the password this way is not recommended, as it ends up in your history and bookmarks.

Glowing Bear works in any modern browser, but it can also be installed as an app for a full-screen experience and an unread badge on its icon: use Install in the address bar or menu on desktop, or Add to Home screen on mobile.
